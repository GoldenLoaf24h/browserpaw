# Client Plugin Compatibility & Architecture

BrowserPaw v5.0.0 standardizes on one execution engine (`browserpaw` CLI), one canonical base skill (`skills/browserpaw/`), and one user-writable self-learning store (`~/.browserpaw`).

The recommended Quick Start in [README.md](../../README.md) and [INSTALL.md](../../INSTALL.md) is **global Agent Skill (`~/.agents/skills/browserpaw`) + npm CLI + unpacked Chrome extension**. Alongside that default, BrowserPaw maintains four synchronized client plugins under `plugins/` so users can install directly through native agent ecosystems while keeping base skills read-only inside plugin directories and self-learned workflows isolated in `~/.browserpaw`.

## Synchronization & Separation Invariants

1. **Single canonical base skill**: Edit only `skills/browserpaw/`, then run `node scripts/sync-skills.mjs`. All four plugin mirrors (`plugins/browserpaw`, `plugins/browserpaw-claude`, `plugins/browserpaw-dsh`, `plugins/browserpaw-hermes`) and the built native skill bundle stay byte-identical and are enforced by `pnpm verify`.
2. **Read-only base skill vs. evolving `~/.browserpaw`**: Base skills remain untouched inside each host's plugin directory. Self-learned site skills (`~/.browserpaw/skills/`), saved CLI recipes (`~/.browserpaw/recipes/`), and `~/.browserpaw/learned-index.json` evolve independently under `~/.browserpaw` without colliding with plugin updates.
3. **Version parity**: `scripts/sync-skills.mjs` and `scripts/validate-docs.mjs` enforce matching versions across root `package.json`, workspace packages, `plugins/browserpaw/plugin.json`, `plugins/browserpaw-claude/.claude-plugin/plugin.json`, `plugins/browserpaw-dsh/package.json`, and `plugins/browserpaw-hermes/plugin.yaml`.
4. **Post-publish Claude Code note**: After `browserpaw@5.0.0` is published to npm, `plugins/browserpaw-claude/` can optionally add a registry-pinned `package.json` + `package-lock.json` (lockfileVersion 2/3, `--ignore-scripts` compatible) so marketplace installs also pre-cache the `browserpaw` package inside Claude Code's plugin cache without introducing a `bin/` directory.
