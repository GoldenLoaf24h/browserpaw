## Historical Live Issues Identified in Initial Build

### 1. OOPIF Full-Frame `read_dom` Injection Timeout

Receipt `.ego-research/oopif-upgrade-live-paw-mvqnee9f-053857e9.json` recorded `passed: false` with initial failure:

```text
executeScript timeout (injection, 4000ms): renderer not acking
```

This represents an architectural bottleneck rather than a simple selector miss. Chrome documentation notes that `runAt` defaults to `document_idle` with `injectImmediately` disabled; pending child frames can hang `allFrames` script execution (see <https://developer.chrome.com/docs/extensions/reference/api/scripting>).

Current source code isolates read-only inspection to individual `documentIds` with `injectImmediately: true`; individual frame failures map to coverage reasons. Regressions in `frame-observation-isolation` pass locally, but Chrome had not yet reloaded the update during that trial. **Until superseded by a passing receipt from a fresh build, OOPIF remains marked as failed.**

### 2. MDN Skill Validation Failure

In `.ego-research/task-skill-upgrade-paw-mvqnee9f-053857e9.json`, task lifecycle succeeded, and `skill.get('mdn-search')` resolved, but subsequent validation failed:

```text
output: data/sources/api must match pattern
"^https://developer\.mozilla\.org/api/v1/search"
```

Root cause: output sanitization stripped full origin URLs containing query parameters as unverified query strings. The source fix preserves public URLs while scrubbing sensitive values, maintaining MDN locale and origin checks. The npm comparison skill passed two fresh trials and was enabled; GitHub execution budgets await extension re-testing. X authenticated sessions were verified; prior false authentication failures from blank loading states were resolved with bounded waiting and distinct loading timeout reporting. The `x-visible-thread` skill verifies parent links, enabling the candidate across two distinct inputs and validating retrieval on a third.
