# BrowserPaw v4.2.0

- **Tag:** v4.2.0
- **Target:** main
- **Date:** 2026-11-12

## Overview

BrowserPaw reduces the default MCP surface to nine tools and makes additional schemas an explicit, per-tool session choice. The 52 canonical tool definitions and execution paths remain available. Known hidden calls do not grow the tool list. This release also adds named persistent CLI sessions and artifact references for large media while preserving complete receipts, bounds session cleanup, consolidates the pending DOM/runtime refactor, and brings historical regressions into the acceptance gate. The local candidate freeze includes cross-process stale-lock recovery, artifact failure receipts, and the final Native package path checks.

MCP remains available as the compact compatibility entry point. Agents with local command execution can use CLI plus Skills for named multi-step sessions and artifact references; the CLI and MCP still share the same browser execution core and task ownership rules.

## Changes

### A. Explicit MCP discovery

- Core consists of `chrome_task`, `chrome_skill`, `chrome_navigate`, `get_windows_and_tabs`, `chrome_switch_tab`, `chrome_read_dom`, `chrome_interact_index`, `chrome_fill_index` and `chrome_tool_docs`. The default serialized schema measures 24,551 bytes against a 26 KiB (26,624-byte) UTF-8 JSON budget. Generated documentation reports actual serialized bytes rather than character-based token estimates.
- `chrome_tool_docs` without arguments returns a compact category index. `category` returns names and purposes; `names` returns complete shared schemas. Neither query changes the list. `names` plus `activateForSession:true` atomically replaces temporary extensions, and an empty array resets to the configured profile. All names are validated before mutation and supported client prefixes are normalized.
- HTTP and stdio no longer activate a whole category when a hidden tool is called. Repeated equivalent selections and changes that do not affect the visible set emit no extra list notification. Sessions release selections on close; selections have no automatic expiry. Stdio serializes selection updates, applies them only after upstream success and ignores acknowledgements arriving after close.
- Native generates documentation from shared definitions with Chrome disconnected. The extension compatibility handler uses the same validator and renderer. Crawl retains its extraction purpose and Full retains all canonical definitions, subject to actual Jev configuration. Authentication, task principals and action safety checks continue on every execution path.
- Portable and Claude plugin configurations now default to Core. DSH guidance explains exact selection and the Full fallback. Hermes retains its independent static wrappers and reads the shared tool-docs schema snapshot; it does not claim a dynamically reduced nine-tool wrapper list.

### B. Dynamic pages, frames and physical input

- The previously committed dynamic-page fixes are included: viewport captures retry transient DOM revision changes at most twice, remain bound to the original tab and geometry, and return an explicit unstable-page error when necessary. Successful captures retain coordinate invalidation checks.
- Standard and fast DOM reads preserve readable main-frame observations when children fail, report incomplete coverage and never substitute a child for a missing main frame. Missing inventory keeps main-frame observations explicitly unverified.
- Cross-world errors preserve message/name/code without serializing arbitrary objects or failing on circular wrappers. Unknown native text insertion is not followed by synthetic rewriting. Multiline replacement uses trusted input without implicit submission.
- Fill preflight projects iframe occlusion coordinates into the root frame. CSS crop dimensions are distinguished from encoded screenshot dimensions when mapping coordinates. Navigation clears cached mouse position; drag release synchronizes the visual cursor. Existing mouse event pacing is retained because the pending timing reduction lacked real-Chrome calibration.
- Settle and confirmation-trap observation share one in-page round trip when supported, with the existing fallback for older engines or failed/invalid combined checks. Dialog state and listeners are released when a tab closes.

### C. DOM decomposition and removal of obsolete paths

- The DOM facade keeps all 117 previous exported names while moving table observation, compact rendering, dropdown extraction, locators, input commitment, semantic Markdown, perceptive signatures, probes, confirmation traps, captcha detection, media insertion, smart scrolling, scroll state and overlay dismissal into 14 focused modules. In-page entrypoints continue through the existing bundled engine; no parallel locator or retry engine is added.
- Remove the unregistered web-fetcher executor and unused click, fill and web-fetcher injection helpers. Caller, dynamic injection and build-entry searches found no active dependency on these deleted files. Current click/fill/read paths and shared schemas remain authoritative.
- Consolidate imports and naming around expected page restrictions, CDP session state, console/network/performance buffers, source downloads, native message validation and session affinity. Preserve cancellation, error receipts and unknown-dispatch/no-retry boundaries.

### D. Native, CLI and Jev lifecycle

- One-shot CLI calls release their own MCP sessions in `finally` after successful results, tool errors, protocol errors, invalid responses and network failures, including a broken initialization stream after the session header arrives. Cleanup has a 1.5-second deadline and cannot replace the original exit status or result. HTTP/parse failures exit nonzero, and uncertain actions are never automatically retried.
- `browserpaw --json TOOL ARGS` (also `TOOL --json ARGS`) preserves `content`, `structuredContent`, `isError`, image/resource blocks and original protocol errors. UTF-8 decoding preserves characters split across network chunks. Plain text output stays compatible; non-text guidance and diagnostics go to stderr. Malformed or non-object JSON arguments fail before dispatch.
- The root CLI and Native package CLI now share one command contract. `session create`, `session call`, `session status` and `session close` reuse the same HTTP MCP session across processes; local records contain only the name, session ID, port and timestamps. Per-session locks serialize calls, stale locks from exited processes can be recovered, and active locks reject concurrent calls.
- One-shot commands still create separate transport sessions. `--artifacts OUTPUT_DIR` writes the complete raw response to `result.json`, extracts image/audio/blob/large text content to `artifacts/`, and prints a manifest containing local paths, sizes and SHA-256 values. Duplicate media payloads in structured content are replaced by references in the manifest, while the raw receipt remains untouched. Session expiry, HTTP errors, malformed responses and artifact failures remain nonzero and never trigger task takeover or action replay. The persistent REPL retains its current task semantics.
- Native disconnect aborts active extension tool controllers. Native transport serializes a request once before sending; SSE disconnect observation follows the response stream instead of accumulating socket listeners. CDP rejects browser-wide close/crash methods. Jev caches CUDA availability per Python executable, closes parent log descriptors and propagates model-download response errors. Build, registration and diagnostic output is made consistent in English.

- CLI HTTP requests now use separate sockets while keeping the same MCP session ID. This fixes the initialization notification failing with HTTP 400 when the SSE response advertised keep-alive and Node reused a socket the server had marked for closure.
- The `fill` alias requires an explicit text argument. Pass an empty string to clear a field. If artifact delivery fails, stdout still returns a JSON error with the actual dispatch state and includes `resultPath` only when the original receipt was saved.

### E. Documentation, release governance and historical reconciliation

- Preserve and migrate 23 agent task records into the byte-identical archive. Add documentation ownership, quality evidence rules, a release procedure, a six-section release template, a release-note validator and CI validation. Historical records and local failure evidence remain preserved.
- Add the pending blueprint, persistent-REPL and comparison documents to their development/archive homes; update active navigation, contributor guidance, troubleshooting and Chinese mirrors. Generated agent navigation excludes scratch artifacts and no longer points at retired root tests. Modified active text files use LF consistently; historical snapshot bytes are preserved.
- Synchronize package/client versions to 4.2.0, the generated tool reference, Hermes schemas and canonical skill mirrors. Only this release's delivered ledger entry is removed from `unreleased.md`; older published features remain historical records rather than new-feature claims.
- Archive four previously uncollected root test files without discarding their working-tree edits. Migrate 56 extension regressions and seven Native safety regressions into suites actually collected by `pnpm verify`. Replace obsolete crop/image assumptions with the current explicit crop and JPEG contract. Retire source-layout assertions that encode removed executors or superseded security rules; the current behavior suites below own those contracts.

## Upgrade & Compatibility

- **Breaking Changes:** the default MCP list is reduced from 16 to nine tools. Category-wide activation is removed. A hidden known tool can still be called directly without expanding the list. No canonical execution tool is removed.
- **Migration Guide:** query `chrome_tool_docs({category:"manage"})`, then select exact names with `{names:["chrome_tab_group_list"],activateForSession:true}`. Include every desired temporary tool in each replacement. `{names:[],activateForSession:true}` resets it. Do not combine `category` and `names`; old category activation returns an actionable error listing possible names. Invalid names leave the prior selection intact.
- **Compatibility Boundaries:** HTTP and stdio support list-change notifications; actual client refresh support differs. Configure `CHROME_MCP_TOOL_PROFILE=full` explicitly when refresh is unsupported. Crawl is unchanged. Explicit Jev promotion is retained as user-requested expansion and is outside the default nine-tool guarantee. Full does not enable unavailable Jev capabilities. Existing task identity, authentication, cancellation and unknown/no-retry rules remain enforced. Hermes static wrappers retain their existing scope.
- **CLI JSON and sessions:** use `browserpaw --json chrome_read_dom '{}'` for one-shot complete receipts, or `browserpaw session create research` followed by `session call research chrome_read_dom '{}'` for cross-command continuity. Use `--artifacts OUTPUT_DIR` to keep binary content out of Agent context. Session expiry does not reconnect or take over tasks. See the [CLI/REPL guide](../../skills/browserpaw/references/cli-repl.md).
- Task-ledger redesign, recovery diagnostics, authentication redesign and dependency replacement remain outside this release.

## Verification Scope

- **Verification Gate:** Run all 14 steps of `pnpm verify` after the final commit with external extension synchronization disabled. The generated `.artifacts/verification/latest.json` records the actual results, timestamps and source fingerprint. Archive it with the candidate's commit, asset hashes and build identity only after the fingerprint matches the committed workspace.
- **Automated Tests:** The Windows gate collects 1854 extension tests in 155 files, 681 Native tests in 38 files, 18 root script test files, simulated E2E and 37 plugin tests. The targeted CLI response and session suites contain 29 tests. One Hermes host integration module is skipped when `tools.registry` and `agent.display` are unavailable. Coverage includes HTTP list refresh notifications, task ownership across CLI sessions, stdio profile discovery, CLI argument validation and artifact write failures, as well as the migrated extension and Native regressions.
- **CI Status:** Linux and Windows GitHub Actions were not run for this local candidate. The workflow includes mirror checks, release-note validation and the complete gate on both platforms; remote results must be checked before publication.
- **Loaded Runtime Checks:** The earlier `doctor --verbose` probe reached an HTTP endpoint and received HTTP 400 during initialization. The previous CLI reproduces that failure against isolated Native 4.2.0. The corrected CLI completes initialization, tool calls and cleanup on that server. Loaded Chrome acceptance is recorded separately with the exact candidate build ID in the local evidence directory. It requires manual loading or reload, matching `chrome_doctor` output and a task on a self-hosted fixture.
- **Boundaries & Exclusions:** Local Windows package smoke and Chrome behavior require separate receipts in the candidate evidence directory. Physical pointer timing, DPR/OOPIF/canvas coverage, Jev hardware/model download, Hermes/DSH host refresh and remote Linux/Windows CI are outside those smoke checks. Existing pre-release evidence and the initial workspace snapshot are retained locally.
