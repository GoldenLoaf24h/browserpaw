# BrowserPaw v5.0.0

- **Tag:** v5.0.0
- **Target:** main
- **Date:** 2026-11-19

## Overview

BrowserPaw moves to a CLI and Agent Skill that operate an installed Chrome extension. The v4.2.0 candidate is the starting point for browser execution, task state, and file receipts.

## Changes

- A shared registry drives browser commands, help, and generated references. Task IDs carry intent across CLI processes. Batch and saved recipes run the same commands and retain step outcomes.
- The Native host serves a versioned loopback protocol and the extension performs browser operations through Chrome Native Messaging. MCP HTTP, SSE, stdio and client wrappers are retired.
- The npm package includes the CLI, host, platform launchers, extension, and Skill. Setup places a durable local host outside the npm cache. Screenshots and large results arrive as file references.
- The extension popup shows connection and build information and provides the Agent Control switch.
- Browser commands reuse the deterministic locator, input, frame, capture, task, and download handlers. Jev, REPL, profile switching and the Hermes and DSH MCP wrappers are retired.
- Page-triggered downloads report the observed browser GUID. Direct URL downloads use Chrome's returned download ID to verify the file before delivering its path.

## Upgrade & Compatibility

- Complete v4 tasks before changing versions. Remove the v4 MCP client configuration, install the v5 CLI and Skill, then load the extension path printed by setup. Follow the [command reference](../COMMANDS.md) for the installed CLI syntax.
- Use `observe`, `click`, and `fill` for the former DOM and index tools. Use `screenshot --out FILE` for images, `task` for task operations, and `batch` for grouped commands.
- v5 uses a dedicated Native name and default port 12307. Existing v4 registrations can be removed after migration.
- Setup updates running Windows installations in place and can request a reload. If Chrome does not reconnect within the verification window, setup returns the manual reload instruction.

## Verification Scope

- **Verification Gate:** `pnpm verify` passes all 13 checks on Windows, including package smoke and generated documentation consistency.
- **Automated Tests:** 1,715 extension tests, 230 Native tests, and 8 root script suites. The verification JSON records the exact source fingerprint and timings.
- **CI Status:** Linux, Windows, and macOS CI verification is pending candidate push.
- **Loaded Runtime Checks:** The npm tarball was installed under a disposable prefix and exercised in Windows Chrome for Testing. Checks cover browser identity, task ownership, iframe and rich-text input, file upload, scoped download and URL file delivery, PNG capture, coordinates, network capture, batch and recipes. The runtime report records the loaded build and executed checks.
- **Boundaries & Exclusions:** The isolated Windows profile accepted the automatic reload request. Setup reported manual reload when the extension did not reconnect. Remote CI, npm registry publication, and normal-profile deployment require a release action.
