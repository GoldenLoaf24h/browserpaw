# BrowserPaw v4.1.0

Status: release candidate. Publication and production runtime acceptance are separate from repository verification. No Git tag or remote release is created by preparing this record.

Release blocker (2026-10-31): page smoke and repository checks passed, but two real long-idle sessions lost their MCP sessions after Native processes exited and restarted. The production idle callback's stdout diagnostic was reproduced as corrupt Native framing; the diagnostic must use stderr. The correction requires a fresh complete gate and long-session runtime acceptance. A healthy reconnected bridge does not prove session continuity. Current evidence locations are maintained in [development boundaries](../development/DEVELOPMENT.md).

## Changes

- Document-bound references, strict frame and locator resolution, shared action checks and receipts preserve failure and unknown-delivery states without replaying uncertain writes. Nested renderer sessions and frame projection support OOPIF interactions.
- Observations budget unique elements across frames, retain long informational text and relevant form state, and reuse unchanged document observations. Supported Shadow roots share naming, focus and hit checks.
- Native input uses guarded editing and trusted keyboard dispatch. Multiline replacement, append and clearing have distinct postconditions; visual cursor notes describe the target rather than an internal element number.
- Durable tasks track page ownership, cancellation, navigation adoption and page budgets. Upload backing files use leases; scoped downloads retain source GUIDs and protect active or unknown transfers during cleanup.
- Persistent JavaScript sessions expose task, page, locator, skill and help methods through the common execution paths. Owned REPL clients ping every four minutes and release their timer when closed.
- Client-neutral Agent Skills include references, scripts and recipe assets. Separate portable, Hermes, Claude Code and DSH packages follow their client contracts. The generic installer ships with Native; learned skills remain in the Native user directory.
- Build provenance excludes transient `.omc` session state. Package manifests and the shared product version are aligned to 4.1.0; the DSH adapter keeps its independently managed version.

## Validation

The release gate is the complete 14-step `pnpm verify`, followed by source fingerprint, deployment hash and production runtime identity checks. The current machine-readable gate result is `.artifacts/verification/latest.json` in the repository. Production acceptance must verify the loaded build after manual extension reload, including observation, input, task cleanup and a persistent REPL session lasting beyond the former idle expiry.

Historical build-specific website tests remain useful regression evidence. They are not renamed as 4.1.0 runtime results. Final acceptance evidence is recorded separately after deployment.

## Boundaries

- The 320-run M7 Agent comparison is stopped. Two historical valid samples do not establish general success rates or the planned 20% wall-time, 30% input-token and 50% reuse improvements. No overall product ranking is claimed.
- Ego native snapshots and Aside's closed browser engine are not fully inspectable; equivalent internal behavior is not claimed.
- Physical window resize/minimize acceptance was waived. Ordinary Chrome popup focus behavior has no engine-level guarantee.
- Hermes end-user verification is performed by the user. Contract tests do not substitute for that workflow or final ChatGPT installation UI acceptance.

The detailed development history remains in [unreleased.md](./unreleased.md) and the [comparison evidence](../development/three-browser-comparison-2026-10-22.zh-CN.md).
