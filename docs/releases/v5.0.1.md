# BrowserPaw v5.0.1

- **Tag:** v5.0.1
- **Target:** main
- **Date:** 2026-11-22

## Overview

BrowserPaw v5.0.1 is a maintenance, reliability, security, and performance release on the v5 CLI-first line. It adds on-demand CLI auto-update with decoupled same-major Chrome extension compatibility, expands and hardens built-in read-only site recipes to 17 workflows with default discovery and automatic upgrades, hardens extension URL/SSRF/CDP/batch-action guardrails and MV3 Service Worker state persistence, optimizes DOM/accessibility hot paths while modularizing `dom-indexer.ts`, and aligns `app/chrome-extension/LICENSE` with the repository-wide AGPL-3.0-or-later license.

## Changes

### On-Demand CLI Auto-Update & Extension Compatibility

- Added an on-demand npm update checker (`browserpaw@latest` stable releases, at most once every 24 hours, no background daemon) that streams and verifies release tarballs with SHA-512 integrity and strict tar path/symlink guards, installs into `~/.browserpaw/cli-versions/{version}`, delegates CLI execution automatically, and refreshes the staged Native Host, bundled recipes, and managed base Skills (`BROWSERPAW_NO_AUTO_UPDATE=1` / `BROWSERPAW_NO_UPDATE_CHECK=1` to opt out).
- Raised the npm registry metadata check timeout to 2.5 seconds, replaced the 24-hour lockout on transient check/install failures with a 10-minute retry backoff (`autoUpdateRetryAfter`), and guarded Windows signal forwarding during delegated CLI execution.
- Decoupled CLI and Chrome extension minor/patch versions via `isCompatibleExtensionVersion` (`MIN_COMPATIBLE_EXTENSION_VERSION = '5.0.0'`): same-major CLI updates work with loaded Chrome extensions `>= 5.0.0` without requiring an immediate extension reload, while `browserpaw status` surfaces `extensionUpdateAvailable`, `extensionLatestVersion`, and `extensionReleaseAsset`.

### Built-In Read-Only Recipes & Skill Engine

- Made trusted bundled read-only recipes discoverable by default in `recipe find`, `recipe list` (`status: bundled`), synced Skills, and Claude/DSH routing tables (display cap raised from 20 to 30), with automatic validation on first `recipe run`, automatic revision upgrades with rollback on validation failure, and preservation of user overrides, disabled skills, and pinned versions.
- Improved skill engine reliability: Ajv input validation clones inputs and applies schema defaults before URL template expansion, caches compiled validators, and deduplicates concurrent same-version `validate` calls.
- Expanded built-in read-only recipes to 17 workflows (adding GitHub repo/readme/search/issue, X/Twitter profile posts, YouTube search/video reader, Bilibili popular/video detail, Reddit subreddit/post reader, and V2EX node/topic reader) with bilingual Chinese/English `recipe find` query aliases.
- Hardened built-in recipes across X/Twitter, Reddit, YouTube, Bilibili, V2EX, npm, MDN, and GitHub Releases with origin guards, filter-before-slice semantics, quote/ad/hidden-element filtering, risk-control/fallback handling (`403`/`412`/`-352`, `__INITIAL_STATE__`, Old Reddit, stale SPA `ytInitialData`), default `hot`/`latest` verification in `v2ex-node-topics`, and clamped `youtube-video-read` `maxSubtitleChars` (at most 10000).

### Chrome Extension Security Guardrails & MV3 Resilience

- Expanded cloud metadata and SSRF blocking across IPv4-mapped/translated/compatible IPv6, NAT64, 6to4, expanded `fd00:ec2::254`, ECS/EKS metadata IPs, and trailing-dot FQDNs.
- Blocked cloud metadata and privileged internal schemes (`chrome://`, `edge://`, `chrome-extension://`, `view-source:`, `data:`, `blob:`) in `chrome_navigate`, and enforced metadata/redirect checks in `network-request` (including `formData` URLs and post-redirect `response.url`).
- Wired `coordinateSpace`, `captureId`, and `screenshotOriginViolation` guardrails into `chrome_batch_actions`, and expanded `chrome_cdp_execute` dangerous-method blocking (`Browser.setDownloadBehavior`, `Page.setDownloadBehavior`, `Target.disposeBrowserContext`) with ref-counted `targetId` timeout cleanup.
- Persisted `screenshotContextManager`, screenshot capture validity records, and CDP session/domain/idle-detach deadlines to `chrome.storage.session`, backed up the 10-minute CDP idle-detach timer with `chrome.alarms`, and added startup rehydration/reconciliation in the MV3 background entrypoint.

### Hot-Path Performance, Modularization & Packaging Governance

- Eliminated O(N^2) linear reverse scans of `window.__mcpElementMap` in `accessibility-tree-helper.js` with a synchronized `WeakMap` reverse index (`window.__mcpElementReverseMap`) and strictly per-call `WeakMap` style/rect/label/interactive caches.
- Introduced per-invocation `DomQueryCache` across `composed-dom.ts`, `locators.ts`, `page-sampling.ts`, `scroll-until-found.ts`, and `inPageDOMPruner`, plus multi-segment ancestor context pruning and shared `visitedRoots` deduplication in `querySelectorAllDeep`.
- Modularized `dom-indexer.ts` (from 5,911 lines to 2,827 lines) by extracting `dom-cache.ts`, `deep-query.ts`, `scroll-until-found.ts`, `highlights.ts`, `modal-scope.ts`, and `inpage-interactions.ts` while preserving all exports and standalone `inPageRemoveHighlights` serialization.
- Hoisted mid-file imports in `native-host.ts`, added popup timer cleanup plus visibility/in-flight polling guards in `entrypoints/popup/App.vue`, expanded `app/native-server/scripts/pack-assets.cjs` prepack checks across all 17 bundled recipes, and aligned `app/chrome-extension/LICENSE` with AGPL-3.0-or-later while retaining upstream MIT attribution in `NOTICE`.

## Upgrade & Compatibility

- **Breaking Changes:** None within the v5 line. All v5 CLI commands, Native Host endpoints (`127.0.0.1:12307`), and `~/.browserpaw` storage schemas remain backward-compatible.
- **Migration Guide:** Existing v5.0.0 users can update via on-demand CLI auto-update or `npm install -g browserpaw@5.0.1 && browserpaw setup`. Existing v4.x users must still follow [docs/MIGRATION.md](../MIGRATION.md) ([Simplified Chinese](../MIGRATION.zh-CN.md)).
- **Compatibility Boundaries:** Requires Node.js `>= 22.6.0` on Windows, macOS, or Linux with desktop Chrome or Chromium. The v5.0.1 CLI stays compatible with loaded Chrome extensions `>= 5.0.0` (`MIN_COMPATIBLE_EXTENSION_VERSION = '5.0.0'`); reloading the v5.0.1 extension is optional for connectivity and required to pick up the Phase 2 security/MV3 and Phase 3 performance improvements.

## Verification Scope

- **Verification Gate:** Local 14-step `pnpm verify` (`scripts/verify.mjs`) recorded in `.artifacts/verification/latest.json`, paired with `pnpm release:check`, `node scripts/sync-skills.mjs --check`, `node scripts/validate-docs.mjs`, `node scripts/validate-agents-docs.mjs`, and `git -c core.whitespace=cr-at-eol diff --check`.
- **Automated Tests:** Full local workspace suites executed inside `pnpm verify`, including root script tests, Chrome extension Vitest suite (covering Phase 2 security/MV3 resilience and Phase 3 hot-path benchmarks/contracts), Native server Jest suite (covering CLI auto-update, extension semver compatibility, skill upgrades, and all 17 bundled recipe contracts), Hermes plugin pytest suite, and packaged npm smoke tests.
- **CI Status:** Local release preparation prior to `git push` and tagging; Linux and Windows GitHub Actions runs will be verified after the push step is authorized.
- **Loaded Runtime Checks:** Phase 1–3 code was deployed and verified live on Chrome at `buildId` `paw-0010a7ee3662` (`manifestVersion: 5.0.0`) prior to version bump; the v5.0.1 extension artifact (`buildId` `paw-683c449d919c`, `manifestVersion: 5.0.1`) is built and deployed to the configured local unpacked directory and verified by `pnpm verify:delivery`, awaiting manual Chrome Reload confirmation via `browserpaw status --json`.
- **Boundaries & Exclusions:** Remote npm publication, GitHub release asset upload, live third-party site scraping against live X/Reddit/YouTube/Bilibili/V2EX sessions after version bump, and post-push cross-platform GitHub Actions runs are outside this local preparation checkpoint.
