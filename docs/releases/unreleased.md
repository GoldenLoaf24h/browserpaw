# BrowserPaw Unreleased Changes Ledger

This ledger tracks changes queued after the current release baseline.

- All v4.1.2 through v5.0.0 changes (including the untagged [v4.2.0](./v4.2.0.md) candidate fixes and CLI transition) have been consolidated into [v5.0.0](./v5.0.0.md).
- Pre-v5 architectural reviews, retired design notes, and legacy MCP test records are preserved under [docs/archive/](../archive/README.md).

## Queued Post-v5.0.0 Changes

- **On-demand CLI auto-update (no background daemon)**: When invoked on demand, `browserpaw` checks the npm registry (`browserpaw@latest` stable releases) at most once every 24 hours, streams and verifies the `.tgz` tarball with SHA-512 integrity and strict tar path/symlink guards, installs into `~/.browserpaw/cli-versions/<version>`, delegates execution automatically, and refreshes the staged host, bundled recipes, and managed base Skills (`BROWSERPAW_NO_AUTO_UPDATE=1` / `BROWSERPAW_NO_UPDATE_CHECK=1` to opt out).
- **Auto-update resilience**: Raised the npm registry metadata check timeout to 2.5 seconds, replaced the 24-hour lockout on transient check/install failures with a 10-minute retry backoff (`autoUpdateRetryAfter`), and guarded Windows signal forwarding during delegated CLI execution.
- **Decoupled CLI vs Chrome extension compatibility**: Added `isCompatibleExtensionVersion` (requiring extension `>= 5.0.0` within the same major version) so minor/patch CLI updates work without forcing an immediate Chrome extension reload; `browserpaw status` succeeds with compatible older extensions and surfaces `extensionUpdateAvailable`, `extensionLatestVersion`, and `extensionReleaseAsset`.
- **Default discovery and automatic updates for trusted bundled skills in `~/.browserpaw`**: Trusted bundled read-only recipes are now visible by default in `recipe find` and `recipe list` (`status: bundled`) and included in synced skill and Claude/DSH routing tables (display cap raised from 20 to 30), while still requiring automatic validation on first `recipe run` (or explicit `recipe validate ID`) before execution and preserving user overrides, disabled skills, pinned rollbacks, and fallback to the previous active revision if validation fails.
- **Skill engine reliability**: Ajv input validation now clones the input object and applies schema defaults before URL expansion (fixing optional parameters such as `reddit-subreddit-posts` `sort`), caches compiled validators, and deduplicates concurrent same-version `validate` calls.
- **Expanded built-in read-only recipes (17 total, adapted from Agent-Reach)**: Added 12 browser-native read-only recipes covering GitHub (`github-repo-readme`, `github-repo-search`, `github-issue-thread`), X/Twitter (`x-profile-posts`), YouTube (`youtube-search-videos`, `youtube-video-read`), Bilibili (`bilibili-popular-videos`, `bilibili-video-detail`), Reddit (`reddit-subreddit-posts`, `reddit-post-read`), and V2EX (`v2ex-node-topics`, `v2ex-topic-read`), along with bilingual Chinese/English `recipe find` query aliases.
- **Built-in recipe hardening across X/Twitter, Reddit, YouTube, Bilibili, V2EX, npm, MDN, and GitHub Releases**: Added origin guards, filter-before-slice semantics, quote/ad/hidden-element filtering, risk-control and fallback handling (`403`/`412`/`-352`, `__INITIAL_STATE__`, Old Reddit, stale SPA `ytInitialData`), fixed `v2ex-node-topics` verification for default `hot`/`latest`, clamped `youtube-video-read` `maxSubtitleChars` to `<= 10000`, and expanded Chinese search keywords.
- **Chrome extension URL/SSRF and action guardrails**: Normalized cloud metadata checks across IPv4-mapped/translated/compatible IPv6, NAT64, 6to4, expanded `fd00:ec2::254`, ECS/EKS metadata IPs, and trailing-dot FQDNs; blocked cloud metadata and privileged internal schemes (`chrome://`, `edge://`, `chrome-extension://`, `view-source:`, `data:`, `blob:`) in `chrome_navigate`; enforced metadata/redirect checks in `network-request` (including `formData` URLs and post-redirect `response.url`); wired `coordinateSpace`, `captureId`, and `screenshotOriginViolation` into `chrome_batch_actions`; and expanded `chrome_cdp_execute` dangerous-method blocking (`Browser.setDownloadBehavior`, `Page.setDownloadBehavior`, `Target.disposeBrowserContext`) with ref-counted `targetId` timeout cleanup.
- **MV3 Service Worker state resilience**: Persisted `screenshotContextManager`, screenshot capture validity records, and CDP session/domain/idle-detach deadlines to `chrome.storage.session`, backed up the 10-minute CDP idle-detach timer with `chrome.alarms`, and added startup rehydration/reconciliation in the background entrypoint.
- **Packaging and documentation contract hardening**: Expanded `prepack` checks in `app/native-server/scripts/pack-assets.cjs` to verify all 17 bundled recipes, staged skill files, host runners, and extension manifest/popup artifacts; added a meta-contract test covering URL template expansion across all 17 built-in recipes; and aligned `docs/MIGRATION.md` and `docs/MIGRATION.zh-CN.md` element ref examples (`e1`/`e2`).
- **Extension hot-path performance and modularization**: Eliminated O(N^2) linear reverse scans of `window.__mcpElementMap` in `accessibility-tree-helper.js` with a synchronized `WeakMap` reverse index (`window.__mcpElementReverseMap`) plus strictly per-call `WeakMap` style/rect/label/interactive caches; introduced per-invocation `DomQueryCache` across `composed-dom.ts`, `locators.ts`, `page-sampling.ts`, `scroll-until-found.ts`, and `inPageDOMPruner`; added multi-segment ancestor context pruning and shared `visitedRoots` deduplication in `querySelectorAllDeep`; extracted `deep-query.ts`, `scroll-until-found.ts`, `highlights.ts`, `modal-scope.ts`, and `inpage-interactions.ts` from `dom-indexer.ts` while preserving all exports and standalone `inPageRemoveHighlights` serialization; hoisted mid-file imports in `native-host.ts` and added timer cleanup plus visibility/in-flight polling guards in `entrypoints/popup/App.vue`.
