Version: 2.9.2 (consistent across package.json ×3). Repository root: D:\workspace\mcp-chrome-master\mcp-chrome-master

## Layered Topology

1. AI Clients (Claude/Cursor/Codex) to MCP Transport Layer (Streamable HTTP+SSE :12306 or stdio)
2. app/native-server (Node20+, Fastify5 + @modelcontextprotocol/sdk 1.11 + @typesafe-ai/sdk 0.6)
3. Chrome Native Messaging (stdio, 4-byte LE length prefix, capped at 1MB per message) to MV3 Service Worker
4. Tool Execution: background/tools/browser/* (48 tools) to chrome.scripting injected inpage-engine or chrome.debugger(CDP)
5. packages/shared: Single source of truth for tool schemas/names/profiles (consumed by both native-server and extension)

## Browser Control Execution Path (Performance Review Baseline)

chrome_read_dom single step = MCP client to native-server(HTTP/SSE or stdio) to native-messaging(1 frame) to SW to executeInPage(allFrames) to in-page pruning+indexing to return-merge(possible secondary inject reindex subframes) to JSON serialization to return through original path. In jev mode, act_toward_goal repeats full read_dom per step (no delta reuse); N steps = N full roundtrips.
